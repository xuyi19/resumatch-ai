## 一、环境配置篇

### 1.1 Conda 创建环境失败：PackagesNotFoundError

**现象：**

```text
PackagesNotFoundError: The following packages are not available from current channels:
  - python=3.11
```

**解决：** 清华镜像同步延迟时，切换经典求解器或指定 conda-forge 频道：

```bash
conda create -n resumatch-ai python=3.11 --solver=classic -y
conda create -n resumatch-ai python=3.11 -c conda-forge -y
```

### 1.2 fitz API 弃用警告

**现象：**

```text
warning: The `fitz` API is deprecated and will be removed in future.
```

**解决：**

```python
# 旧写法
import fitz
# 新写法
import pymupdf
```

### 1.3 本机 8765 端口被其它应用占用

**现象：** 启动报端口占用，或桌面版窗口打开的是别的应用页面。

**原因：** 本机 8765 常驻「蓝笔申论 BluePencil」等其它软件。

**解决：** `run.py` 启动前探测端口，被占用自动顺延 8766+；单实例锁只认 `/_sig` 签名响应，不误伤其它应用。

## 二、数据库篇

### 2.1 从 MySQL 迁移到 SQLite 的动机与结论

**背景：** 早期版本使用 MySQL（asyncmy 驱动），部署门槛高（用户需自装数据库、处理连接串转义、字符集），与"桌面 exe 零配置分发"目标冲突。

**结论：** 全量迁移到内置 SQLite（aiosqlite）。数据量级（个人简历诊断记录）完全在 SQLite 舒适区内，换来：

- 免安装、免配置，库就是 `data/resumatch.db` 一个文件，随目录整体分发/备份；
- 连接串固定，`config.py` 内置默认值，用户无感知；
- 早期 MySQL 的连接池参数调优（pool_recycle / pre_ping 防空闲断连）问题整体消失。

### 2.2 StaticPool 共享连接导致并发游标错乱

**现象：** 请求会话与后台诊断任务会话并发写库时，偶发游标被 reset、事务内容丢失。

**原因：** `StaticPool` 全局共享单连接，两个会话在同一连接上交错 commit 时互相干扰。

**解决：** 改用 `AsyncAdaptedQueuePool`（每会话独立连接）+ WAL：

```python
engine = create_async_engine(
    url, poolclass=AsyncAdaptedQueuePool,
    connect_args={"check_same_thread": False, "timeout": 30},
)

@event.listens_for(engine.sync_engine, "connect")
def _sqlite_pragma(dbapi_connection, connection_record):
    cursor = dbapi_connection.cursor()
    try:
        cursor.execute("PRAGMA journal_mode=WAL")     # 多读单写并发
        cursor.execute("PRAGMA busy_timeout=5000")    # 缓解写锁竞争
    finally:
        cursor.close()
```

### 2.3 create_all 不会给已存在的表加列（老库升级）

**现象：** 新版本代码加了 `owner_id` 列，老用户的库启动后报"no such column"。

**原因：** SQLAlchemy 的 `Base.metadata.create_all` 只建缺失的表，不改已存在的表结构。

**解决：** 新增列统一登记在 `app/core/db.py` 的 `_SCHEMA_NEW_COLUMNS`（表名 → [(列名, DDL)]），启动时 `ensure_schema_columns()` 用 `PRAGMA table_info` 检查后 `ALTER TABLE` 补列并回填默认值。机制幂等，lifespan（生产）与 conftest（测试）共用同一份登记。

**教训：** 给已有表加列必须走显式迁移登记，不能只改实体类。

### 2.4 SQLite 时间戳是 UTC naive

**现象：** Web 每日配额（按自然日限次）统计出错。

**原因：** `server_default=func.now()` 在 SQLite 里写的是 UTC naive 时间，直接与本地 `datetime.now()` 比较会差时区。

**解决：** 所有日期比较统一按 UTC 计算：

```python
today_start = datetime.now(timezone.utc).replace(hour=0, minute=0, second=0, microsecond=0)
```

启动补偿的 cutoff 比较同理。

## 三、LLM / 多智能体篇

### 3.1 DeepSeek 402 Insufficient Balance

**现象：**

```text
Error code: 402 - {'error': {'message': 'Insufficient Balance'}}
```

**解决：** 充值少量金额，或改用智谱 GLM-4-Flash（免费）。产品层面：设置页提供连接测试（`POST /settings/test-llm`），报错信息直接透传给用户。

### 3.2 with_structured_output 在 DeepSeek 上不返回 JSON

**现象：**

```text
Invalid JSON: expected value at line 1 column 1
input_value='教育经历：\n- 学...'
```

**原因：** DeepSeek 等模型不支持 tool calling，`with_structured_output` 底层走的 function calling 路径直接失效。

**解决：** 手写"Schema 注入 + 正则兜底 + 失败重述"三层容错：

```python
async def call_llm_for_json(prompt, schema, llm_config=None):
    schema_desc = json.dumps(schema.model_json_schema(), ensure_ascii=False)
    full_prompt = f"{prompt}\n\n请严格返回符合下面 JSON Schema 的 JSON 对象：\n{schema_desc}\n\n直接输出 JSON："
    for attempt in range(max_retries + 1):
        resp = await llm.ainvoke(full_prompt)
        content = resp.content.strip()
        match = JSON_PATTERN.search(content)   # 剥 ```json 标记 + 截首个完整 JSON
        if match:
            content = match.group(0)
        try:
            return schema.model_validate(json.loads(content))
        except Exception as e:
            full_prompt += f"\n\n上次输出解析失败（{e}），请严格只输出 JSON。"
```

**通用性：** 适配任何 OpenAI 协议模型（DeepSeek / 智谱 / Ollama），是模型可插拔的基础。

### 3.3 Pydantic 字段类型校验失败：overall 收到 {"score": 80}

**现象：**

```text
Input should be a valid integer [type=int_type, input_value={'score': 80}]
```

**原因：** LLM 看前面的字段都是 `ScoreItem`，惯性把 `overall` 也写成嵌套对象。

**解决：** Pydantic `field_validator` 兼容两种写法：

```python
@field_validator("overall", mode="before")
@classmethod
def coerce_overall(cls, v):
    if isinstance(v, dict):
        return v.get("score", 0)
    return v
```

### 3.4 诊断节点温度分层

**经验：** 不同性质的任务用不同温度——抽取类低温（parser 0.1 / job_analyze 0.2）保证稳定忠实，评分类 0.2 可复现，生成类高温（rewriter 0.5）保证多样性。全部塞一个温度要么输出发散要么改写僵化。

### 3.5 LangGraph 并行分支的 error 合并

**问题：** parser 与 job_analyze 并行执行后，若两者同一步各写一次 `error`，TypedDict 默认覆盖语义会丢一个分支的结果。

**解决：** 给 `error` 字段挂自定义 reducer，保留首个非空值：

```python
def _merge_error(existing, new):
    return existing or new

class DiagnosisState(TypedDict, total=False):
    error: Annotated[str | None, _merge_error]
    messages: Annotated[list, operator.add]
```

## 四、前后端联调篇

### 4.1 浏览器缓存导致页面不更新

**解决：** 后端对 HTML 响应加 `Cache-Control: no-cache`；前端开发用强刷（Ctrl+Shift+R）。改完代码看不到效果先怀疑缓存。

### 4.2 前端空态防护

**教训：** 依赖路由参数/存储的页面必须有空态分支，否则会在异常数据上循环发请求。编辑器数据源按优先级回退（localStorage → sessionStorage → 接口），全部为空时给出明确提示而非白屏。

### 4.3 接口改动要全链路检查

**教训：** 移除 `city` 字段、`/live/analyze` 改请求体时，需同步改后端 Schema、前端表单、历史展示三处；漏一处就会出现"提交正常但列表页残留旧字段"之类的隐性错位。

### 4.4 hash 路由影响自动化与分享链接

**坑：** 前端路由是 hash 模式，正确地址形如 `http://127.0.0.1:8765/#/analyze`——不带 `#` 会打到后端根路径。自动化测试/截图导航必须带 `#`。

### 4.5 前端兼容后端多种返回格式

**问题：** LLM 生成的优化简历里，教育/工作/项目可能是 `["2017.09-2021.06 XX大学 计算机 本科"]` 字符串数组，也可能是对象数组。

**解决：** 前端 `normalizeArray` 统一归一化：对象直接取字段；字符串按时间正则 + 空格切分解析出 school/company/time 等字段，剩余行拼进 desc。

## 五、桌面打包篇

### 5.1 PyInstaller 打包体积失控

**问题：** 直接打包体积巨大。

**解决：** 排除清单裁剪：MySQL 驱动（残留依赖）、torch、Chromium 等；one-folder 模式（比 one-file 启动快），产物 zip 约 55MB。排除清单里的 playwright 字符串是有意保留的防御性排除。

### 5.2 打包后资源路径与数据目录

**坑：** 打包后 `__file__` 不可靠。

**解决：** `config.py::_resolve_base_dir` 按 `sys.frozen` 区分：打包后取 exe 所在目录（数据/配置跟随 exe），开发时取 backend/。前端静态资源打包进 `_MEIPASS/web`，运行时按同一规则解析。

### 5.3 单实例锁不能只看端口

**问题：** 简单地"端口被占用就退出"会误伤其它应用（本机 8765 被 BluePencil 占用就直接把用户挡在门外）。

**解决：** 启动时请求 `http://127.0.0.1:<port>/api/v1/_sig`，只有响应匹配 ResuMatch 签名才认为是自己的旧实例（拉到前台），否则视为端口被占、顺延换端口。

### 5.4 pywebview 窗口与浏览器回退

**方案：** `desktop.py` 默认起 pywebview 原生窗口；pywebview 初始化失败（如缺 WebView2 运行时）自动回退打开系统浏览器；`--no-browser` / `--browser` 参数可强制指定。后端 uvicorn 以子进程方式由启动器拉起。

## 六、模板与照片篇

### 6.1 Word 中文回落默认字体

**现象：** python-docx 设置了字体名，Word 里中文仍是默认宋体/等线。

**原因：** 中文字体需要单独设置 eastAsia 属性，只设 `font.name` 只对西文生效。

**解决：**

```python
def _set_cjk(run, east: str) -> None:
    rPr = run._element.get_or_add_rPr()
    rFonts = rPr.find(qn("w:rFonts"))
    if rFonts is None:
        rFonts = OxmlElement("w:rFonts")
        rPr.append(rFonts)
    rFonts.set(qn("w:eastAsia"), east)   # 如 "宋体"
```

### 6.2 照片端点 404：photo_id 正则误要求扩展名

**现象：** 上传成功返回的 photo_id，`GET /resumes/photo/{photo_id}` 却 404。

**原因：** 校验正则一开始写成了要求带 `.jpg/.png` 后缀，而服务端返回的是裸 32 位十六进制 ID。

**解决：** 统一约定 photo_id = uuid4().hex（裸 ID，不带扩展名），正则 `^[0-9a-f]{32}$`；读取时用 `glob(f"{photo_id}.*")` 定位实际文件。

### 6.3 照片上传安全：魔数白名单 + uuid 文件名

**方案：** 只信文件内容不信扩展名——魔数白名单（JPG `\xff\xd8\xff` / PNG `\x89PNG\r\n\x1a\n`）判定真实格式；文件名用 uuid4().hex 生成，用户输入永远不进路径，天然防路径穿越；大小限 5MB。

### 6.4 前端预览与 Word 导出的版式同步

**问题：** 10 套模板各自实现一套前端 HTML 预览成本高且易与 docx 实现漂移。

**方案：** 预览与导出共用同一套"模板参数语义"（页眉版式 center/left/inline/sidebar、标题标记 `▍`/`●`/`—`、是否 bullet、衬线、标题文案、色彩表）：前端 `ResumePreview.vue` 用配置表 + CSS 变量驱动渲染，参数取值与 `docx_generator.py` 的 TEMPLATES/TEMPLATE_CATALOG 一一对应。模板目录由后端 `GET /resumes/templates` 下发，保证两端同源。

## 七、流程与协作篇

### 7.1 会话崩溃导致未落盘编辑丢失

**现象：** 一次会话崩溃导致部分已"完成"的编辑（deps.py、config/db/entities、README、改造计划）实际未写入磁盘。

**解决：** 全部重做并验证。**教训：** 大改动尽早让用户确认或 git 提交，不要把大量工作压在未保存状态。

### 7.2 测试环境与 lifespan

**坑：** `ASGITransport` 不触发 FastAPI lifespan，测试里建表/补列不会自动执行。

**解决：** conftest 手动 `create_all` + `ensure_schema_columns`，与生产 lifespan 共用同一份登记，保证测试库结构与真实库一致。

## 八、经验教训汇总

### 架构层面

- **先跑通最小闭环**：一份简历 + 一段 JD → 一份报告，再扩展模板、导出、网站形态
- **零配置优先**：SQLite + config.json 预置，把"能不能跑起来"的门槛降到双击 exe
- **接口改动要全链路检查**：Schema、前端表单、列表展示、测试四处同步

### 编码层面

- **LLM 输出永远不可信**：Schema 注入 + 正则兜底 + 重述重试 + field_validator 防御
- **并行分支的共享状态要显式声明 reducer**：LangGraph 的 Annotated 合并语义
- **给已有表加列必须走迁移登记**：create_all 只建表不改表
- **日期统一按 UTC 比较**：SQLite 时间戳是 naive UTC

### 安全层面

- **文件上传只信内容不信扩展名**：魔数白名单 + 服务端生成文件名
- **数据隔离在应用层统一注入**：owner_id 过滤走依赖注入，避免每个端点各自实现漏掉

### 调试层面

- **加 `logger.exception` 打印完整堆栈**
- **浏览器 F12 Network + Console 解决 90% 前端问题**
- **pytest 全过再提交**：测试用例是重构安全网（当前 15 项）
