## 一、环境配置篇

### 1.1 Conda 创建环境失败：PackagesNotFoundError: python=3.11

**现象：**

```text
PackagesNotFoundError: The following packages are not available from current channels:
  - python=3.11
```

**原因：**

- Conda 镜像源（清华镜像）同步延迟
- 新版 libmamba 求解器在 Windows 上兼容性差

**解决：**

```bash
# 方案 A：切换经典求解器
conda create -n resumatch-ai python=3.11 --solver=classic -y

# 方案 B：指定 conda-forge 频道
conda create -n resumatch-ai python=3.11 -c conda-forge -y

# 方案 C（最终采用）：改用 Python 自带的 venv
# 直接装 Python 3.11 安装包，然后用 venv
```

**最终选择：** Python 3.11 + venv，避免 Conda 的复杂依赖求解。

### 1.2 fitz API 弃用警告

**现象：**

```text
warning: The `fitz` API is deprecated and will be removed in future. Use `import pymupdf` instead.
```

**解决：**

```python
# 旧写法
import fitz

# 新写法
import pymupdf
```

## 二、数据库篇

### 2.1 MySQL 密码含特殊字符导致连接失败

**现象：** 密码 `Resumatch@2024` 在 URL 里被 `@` 截断。

**解决：** URL 编码

```text
@ → %40
# → %23
/ → %2F
```

**示例：**

```text
mysql+asyncmy://resumatch:Resumatch%402024@127.0.0.1:3306/resumatch?charset=utf8mb4
```

### 2.2 中文乱码

**原因：** 数据库字符集不是 utf8mb4。

**解决：** 建库时指定字符集

```sql
CREATE DATABASE resumatch
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

### 2.3 Lost connection to MySQL server during query（2013）

**现象：** 长时间任务（加载语义模型 3 分钟）后，session 关闭时连接已断。

**原因：**

- MySQL 默认 `wait_timeout=28800`（8 小时），但客户端会主动断开空闲连接
- 模型加载期间 session 一直空闲，被服务器掐断

**解决：**

```python
# app/core/db.py 中加连接池参数
engine = create_async_engine(
    settings.DB_URL,
    poolclass=AsyncAdaptedQueuePool,
    pool_size=10,
    max_overflow=20,
    pool_recycle=1800,      # 30 分钟回收
    pool_pre_ping=True,     # 取连接前先 ping
)
```

**更根本的方案：** 先加载模型，再打开 session。

## 三、爬虫篇

### 3.1 智联招聘接口猜错，抓到 0 条数据

**现象：** 日志 `共抓取到 0 条职位`。

**原因：**

- 智联页面是服务端渲染（SSR），职位数据不在 XHR 接口里
- 之前猜的接口路径 `/api/i/zl/zlgj` 是错的

**排查方法：** 写 `debug_crawler.py` 打印所有 XHR 请求，保存整页 HTML。

**解决：** 改用 DOM 解析，直接解析 `.job-card` 元素。

### 3.2 翻页失效，只抓到 20 条

**现象：** 滚动 4 次，卡片数一直是 20。

**原因：**

- 智联现在分页显示，每页 20 条
- 滚动不触发懒加载

**解决：** 改用多关键词抓取

```python
keywords = ["python开发", "后端开发", "数据分析", ...]
for kw in keywords:
    jobs = await crawler.fetch_job_list(keyword=kw, ...)
```

**效果：** 8 个关键词 × 20 条 ≈ 132 条（去重后）。

### 3.3 字段解析混乱：experience 混进 tags

**现象：** tags 里有 `"1-3年"`、`"软件/IT服务"` 等非技能内容。

**解决：** 加正则 + 白名单过滤

```python
EDU_SET = {"大专", "本科", "硕士", "博士", "不限"}
EXP_PATTERN = re.compile(r"^(\d+[-~]\d+年|\d+年以上|经验不限|应届)$")

for line in lines:
    if edu is None and line in EDU_SET:
        edu = line
    elif exp is None and EXP_PATTERN.match(line):
        exp = line
    else:
        tags.append(line)
```

### 3.4 重复 source_id 导致事务被污染

**现象：**

```text
IntegrityError: Duplicate entry 'zl_xxx' for key 'ix_jobs_source_id'
This Session's transaction has been rolled back due to a previous exception
```

**原因：**

- INSERT 冲突后没 rollback，整个 session 进入脏状态
- 后续 19 条哪怕能插也全部失败

**解决：** 先查后插

```python
async def process_with_stats(self, jobs_data):
    for job in jobs_data:
        # ★ 先 SELECT
        exists = await session.execute(
            select(Job.id).where(Job.source_id == cleaned["source_id"])
        )
        if exists.scalar_one_or_none() is not None:
            skipped += 1
            continue
        # 再 INSERT
        session.add(Job(**cleaned))
        await session.flush()
    await session.commit()
```

### 3.5 Windows 上 Playwright 异步版与 uvicorn 事件循环冲突

**现象：**

```text
RetryError[]  # 爬虫重试 3 次全失败
```

**根因：**

- uvicorn 在 Windows 上用 SelectorEventLoop
- Playwright 需要 ProactorEventLoop（要用 subprocess 启动浏览器）
- Selector 不支持 subprocess → 启动失败

**解决：** 改用同步版 Playwright + `asyncio.to_thread`

```python
# 新建 app/crawlers/zhilian_sync.py，用 sync_playwright
from playwright.sync_api import sync_playwright

class ZhilianCrawlerSync:
    def fetch_job_list(self, ...):
        with sync_playwright() as p:
            ...

# 在异步服务里调
jobs = await asyncio.to_thread(crawler.fetch_job_list, keyword=kw, ...)
```

**原理：** `asyncio.to_thread` 把同步代码扔到独立线程，线程有自己的 loop，不受 uvicorn 影响。

### 4.2 with_structured_output 在 DeepSeek 上不返回 JSON

**现象：**

```text
Invalid JSON: expected value at line 1 column 1
input_value='教育经历：\n- 学...统开发的能力。'
```

**原因：** DeepSeek 不支持 tool calling，`with_structured_output` 底层走的是 function calling 路径。

**解决：** 手写 JSON 结构化输出

```python
async def call_llm_for_json(prompt, schema, llm_config=None):
    llm = get_llm(...)
    schema_desc = json.dumps(schema.model_json_schema(), ensure_ascii=False)

    full_prompt = f"""{prompt}

请严格返回符合下面 JSON Schema 的 JSON 对象：
{schema_desc}

直接输出 JSON："""

    for attempt in range(max_retries + 1):
        resp = await llm.ainvoke(full_prompt)
        content = resp.content.strip()
        # 去掉 ```json 标记
        match = JSON_PATTERN.search(content)
        if match:
            content = match.group(0)
        return schema.model_validate(json.loads(content))
```

**通用性：** 适配任何 OpenAI 协议模型（DeepSeek / 智谱 / Ollama）。

### 4.3 Pydantic 字段类型校验失败：overall 收到 {"score": 80}

**现象：**

```text
Input should be a valid integer [type=int_type, input_value={'score': 80}]
```

**原因：** LLM 看前面的字段都是 `ScoreItem`，惯性把 `overall` 也写成嵌套对象。

**解决：** Pydantic `field_validator` 兼容两种写法

```python
@field_validator("overall", mode="before")
@classmethod
def coerce_overall(cls, v):
    if isinstance(v, dict):
        return v.get("score", 0)
    return v
```

### 4.4 HuggingFace 模型下载慢/失败

## 五、前后端联调篇

### 5.1 Lost connection + 前端 400 循环请求

**现象：** 终端刷屏 `POST /api/v1/match/with-diagnosis 400`。

**原因：**

- 直接打开 `result.html`，没走首页
- `sessionStorage` 里没有 `resume_id`
- 旧版 `result.html` 无防护，在 alert 阻塞后仍触发请求

**解决：**

1. 不直接打开 `result.html`
2. `result.html` 里加防护：

```javascript
if (!resumeId) {
    showEmptyState();
    return;   // ★ 直接返回，不发请求
}
```

3. URL 参数双保险：跳转时带 `?rid=xxx`

```javascript
location.href = `/frontend/result.html?rid=${rid}&top_k=${topK}`;
```

### 5.2 app/main.py 粘贴错误：SyntaxError

**现象：**

```text
app.mount("/frontend", ...)age": f"{settings.APP_NAME}..."
```

**原因：** 粘贴时旧代码残留，`app.mount(...)` 和 `return {...}` 粘在一行。

**解决：** 整体替换 `main.py`，不要局部粘贴。

### 5.3 cannot import name 'admin' from 'app.api.v1'

**现象：** `ImportError: cannot import name 'admin'`。

**原因：** `main.py` 里 import 了 `admin`（定时爬虫方案），但切到"实时爬虫"模式后没用 `admin.py`。

**解决：** 改 import 语句

```python
# 旧
from app.api.v1 import admin, health, job, live, match, resume

# 新
from app.api.v1 import health, job, live, match, resume
```

### 5.4 浏览器缓存导致页面不更新

**现象：** 改了代码但浏览器显示旧界面。

**解决：**

1. 后端禁用缓存（`main.py` 加中间件）

```python
@app.middleware("http")
async def no_cache_html(request: Request, call_next):
    response = await call_next(request)
    if request.url.path == "/" or request.url.path.endswith(".html"):
        response.headers["Cache-Control"] = "no-cache, no-store, must-revalidate, max-age=0"
    return response
```

2. 前端清缓存：Ctrl + Shift + Delete
3. 无痕窗口：Ctrl + Shift + N

### 5.5 'JobPipeline' object has no attribute 'process_with_stats'

**现象：**

```text
AttributeError: 'JobPipeline' object has no attribute 'process_with_stats'
```

**原因：** `live_pipeline_service.py` 用新方法，但 `pipeline.py` 没同步更新。

**解决：** 给 `pipeline.py` 加 `process_with_stats` 方法，返回 `(inserted, skipped)` 元组。

**教训：** 接口改了要同步所有调用方。

## 七、经验教训

### 架构层面

- **先跑通最小闭环**：一条 JD → 一份简历 → 一个分数 → 一份报告，再扩展
- **异步与同步不要混用**：uvicorn 的 loop 是 Selector，遇到 Playwright 要隔离
- **接口改动要全链路检查**：加方法别忘了所有调用方

### 编码层面

- **LLM 输出永远不可信**：加 `field_validator` 兼容异常格式
- **SQLAlchemy 事务是"脏"的**：一次失败后必须 rollback 或先查后插
- **前端要有防护**：sessionStorage 可能为空，URL 参数双保险
- **文件路径要用 pathlib**：跨平台稳

### 调试层面

- **加 `reraise=True`**：让 `RetryError` 抛原始异常，看到真正错误
- **加 `logger.exception`**：打印完整堆栈
- **用 `asyncio.to_thread`**：同步代码扔线程池，不阻塞事件循环
- **浏览器 F12 是必备工具**：Network + Console 能解决 90% 前端问题

### 开发习惯

- **整体替换文件比局部粘贴安全**
- **Ctrl+S 保存再运行**，别问为什么代码没生效
- **改完代码强制刷新**：Ctrl + Shift + R
- **测试脚本统一放 `scripts/`**：加 `sys.path` 修正

## 八、答辩可讲的技术亮点

如果老师问"你遇到最大的技术难点是什么"，可以答：

> "Windows 上 FastAPI + Playwright 的事件循环冲突是最难啃的坑。uvicorn 默认用 SelectorEventLoop，而 Playwright 需要 ProactorEventLoop 支持 subprocess。异步版的 Playwright 会直接崩溃。我的方案是改用同步版 Playwright + `asyncio.to_thread`——把同步的爬虫代码扔到独立线程里跑，线程有自己的事件循环，不受 uvicorn 影响。这样既保留了 FastAPI 的异步性能，又能稳定运行爬虫。"

**这段话体现的工程能力：**

- 理解事件循环底层机制
- 知道异步/同步的边界
- 用工程手段解决平台差异
