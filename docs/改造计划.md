## 三、M56 投递直达模块（活跃，P0）

> 调研结论（GitHub 业界对照）：全自动代提交已被证伪——国内四大平台无个人开放 API（拉勾已破产下架），Playwright 复用登录态路线封号真实（Boss 2026 冻结约 2.5 万账号；get_jobs 8.7k★ 自述智联模块烂掉），海外 AIHawk 12k★ 自动投递核心已转商业闭源。**验证可行的半自动路线**：Simplify Copilot（统一档案+预填+用户手点提交，2M 用户）、offer-hunter（评分+招呼语+只复制不代发+本地台账）。

**定位与红线**：不代用户自动提交、不抓取平台数据（深链仅为 URL 跳转官方页）、LLM 生成材料禁止编造档案外信息。

- [x] **M56.1 平台深链直达（P0）✅**：`utils/job_links.py` 按岗位名+公司+城市生成 Boss/智联/猎聘/牛客搜索深链（内置常用城市码表；Boss `zhipin.com/web/geek/job?query=&city=`、智联 `sou.zhaopin.com/?kw=&jl=`、猎聘 `liepin.com/zhaopin/?key=`）；岗位卡「🚀 投递」弹层直达官方搜索页；跳转后一键标记「已投递」联动 M49 状态机

## 四、附：独立「岗位爬取 + 投递」工具可行性分析（2026-10-08 定稿）

> 背景：设想单独做一个岗位爬取+投递工具与知岗搭配。结论先行：**全自动爬取+代投递不可行也不建议做**；可行替代为「半自动投递台」轻量形态，能力由知岗 M56 内建覆盖，无需独立工具。

| 维度 | 分析 |
|------|------|
| 技术可行性 | 爬取「能跑但永远在对抗」：Boss 有 `__zp_stoken__` 签名加密 + 强风控，智联/猎聘/51job 相对宽松但均有验证码与频率墙，平台一改版即失效（get_jobs 8.7k★ 作者自述智联模块已烂）。代投递技术成熟（Playwright 复用登录态模拟点击），但属于高危自动化操作 |
| 平台风险 | Boss 2026 年冻结约 2.5 万自动化账号（实证）；LinkedIn 封号先例；国内四大平台均无个人开放 API（拉勾已下架）——封号损失由工具使用者承担 |
| 法律合规 | 爬取违反平台 ToS；批量爬取用于产品化服务有《反不正当竞争法》败诉判例，情节严重涉「非法获取计算机信息系统数据罪」；个人自用属灰色，**分发工具=放大他人风险**（用户账号冻结 + 工具方连带责任），且知岗是分发形态的桌面软件，风险会传导给全部用户 |
| 维护成本 | 无官方 API ⇒ 风控对抗无休止，失效频率为周级，与知岗「零配置、离线可用」的产品基调冲突 |
| ✅ 可行替代 | **半自动投递台**（用户手点提交，工具只做辅助，零封号/法律风险）：① 深链搜索直达（知岗 M56 已内建同能力）；② 浏览器书签/插件收集用户自有数据进台账；③ 招呼语/材料包剪贴板辅助粘贴；④ 本地台账与知岗岗位库互通 |

**决策**：不做独立爬取+代投递工具；知岗侧按 M56 推进已覆盖大部分价值。

## 五、开发流程规范（每个里程碑都走这套）

1. **计划**：拆 2~4 个可验证的子任务（后端/前端/测试），写进本文档对应编号下
2. **实施**：后端改动必须同步 `_SCHEMA_NEW_COLUMNS`（新列）与测试；前端必须 build 通过
3. **验证**：`E:\conda\envs\resumatch-ai\python.exe -m pytest backend/tests -q` 全绿 + `npm run build --prefix frontend` 通过；UI 改动浏览器实测
4. **记录**：docs/修改日志.md 追加条目（含根因/方案/验证数据）→ 本文档对应项打勾 → project_memory 沉淀教训
5. **提交**：里程碑完成后即 commit + push（gitee + github 双远端，分支「数据库更换」）——**不积攒未提交改动**
6. **发版**（仅用户要求时）：版本号三处同步（`app/__init__.py` → `package.json` → `ChangelogView.vue`）→ `build_desktop.py` 打包 → release/ 仅留 1 版 → tag + push

## 七、环境与约定备忘

- 后端 conda 环境（真实路径）：`E:\conda\envs\resumatch-ai\python.exe`（`C:\Users\许\.conda\envs\resumatch-ai` 是 junction，可能被清理工具删除）；测试：`cd backend && python -m pytest tests/`
- 环境若被清理工具破坏：`Lib/` 标准库与 `DLLs/` 可用 python.org 嵌入包（3.10.11）补齐，`site-packages` 通常完好；`pip` 用 get-pip.py 的 `--target` 方式绕过 `Scripts\*.exe` 被杀软拦截的问题
- 测试隔离：conftest 在导入 app 前把 `DB_URL` / `PHOTOS_DIR` 指向 `backend/tests/.tmp/`（自检断言，隔离失效即报错），并手动 create_all + ensure_schema_columns（ASGITransport 不触发 lifespan）；测试不写开发库
- 老库升级模式：新增列统一登记在 `app/core/db.py` 的 `_SCHEMA_NEW_COLUMNS`
- 本机 8765 端口常被「蓝笔申论 BluePencil」占用，服务会顺延 8766+
- 前端路由为 hash 模式（`#/app/...`），自动化导航必须带 `#`
- SQLite 时间戳为 UTC naive；配额/启动补偿的日期比较均按 UTC
