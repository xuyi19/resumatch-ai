## M16 跨重启恢复 + 草稿暂存（2026-09-21）

**修改内容**
- **SqliteSaver 持久化**：交互诊断图 checkpointer 由 MemorySaver 升级为 SqliteSaver（`data/checkpoints.db`，进程级单例 + `check_same_thread=False`），`interrupt()` 暂停时的图状态落文件快照，重启不丢；快照库初始化失败自动降级 MemorySaver
- **waiting 任务跨重启恢复**：`diagnosis_records` 新增 `questions` / `clarify_ctx` JSON 列（老库自动补列），进入 waiting_clarify 时问题列表与恢复上下文（jd_text / city / llm_config / enable_refine / resume_name / resume_id）落库；`resume()` 内存无条目时自动从 DB 重建；启动 lifespan 补偿扫描 waiting 记录重建进内存表；无上下文的老版本遗留任务优雅标记 failed 而非永远悬置
- **前端追问草稿暂存**：追问回答实时存 `localStorage clarify_draft_{taskId}`，误关页面重开不丢已填内容，提交成功后清除
- 打包 hiddenimports 补 `langgraph.checkpoint.sqlite` / `sqlite_vec`；新增 `test_live_recovery.py` 3 项集成测试

**遇到的问题与解决**
| 问题 | 解决 |
| --- | --- |
| `_default_db_file()` 首版引用了不存在的 `app_settings.db_url`，且调用位于降级 try 块内——ImportError 被静默吞掉，SqliteSaver 永远降级 MemorySaver，功能整体静默失效 | 修正为 `settings.DB_URL`；教训：**降级兜底的 try 块会把实现错误伪装成环境问题**，依赖降级的路径必须有测试或日志暴露 |
| SqliteSaver 快照库（tests/.tmp/checkpoints.db）跨 pytest 运行留存，`test_interactive_clarify_pause_and_resume` 同 thread_id 重跑时合并上次已完成运行的 channel 残留（suggestions 非空）导致断言失败 | conftest 启动时清理 `checkpoints.db*` 残留（MemorySaver 时代进程退出即清空，无此问题） |
| `.tmp` 测试库跨运行留存，legacy 用例固定 task_id `legacy-wait` 触发 UNIQUE 冲突 | 用例改 `uuid4().hex` 随机 id |
| 测试里 `LivePipelineService.TASKS` 报 AttributeError | 内存任务表是模块级 dict（`live_pipeline_service.TASKS`）而非类属性 |
| 计划中的 scorer 并行化优化 | 核实后**不做**：scorer 是单次 LLM 调用评六维，证据检索纯 CPU 毫秒级——无并行收益，属伪优化 |

**验证**：pytest 25 过（22+3，含模拟重启后 Command(resume) 从 DB 重建续跑成功的端到端断言）；`npm run build` 过。

## M15 独立简历创建 + 仓库入口（2026-09-21）

**修改内容**
- **独立创建简历模式**：编辑器支持无任务进入——新增路由 `/editor`（原 `/editor/:taskId` 保留），首页新增「✍️ 免费创建简历」入口；空白模式（taskId 为空）不拉取任何任务数据，编辑内容自动存 `resume_edit_blank`（localStorage），与诊断链路的存档键隔离互不污染；顶栏标题区分「创建简历 / 简历编辑」，无任务时隐藏「← 返回报告」
- **开源仓库跳转**：首页 CTA 区新增 GitHub / Gitee 链接（官方 SVG 图标，新窗口打开），地址与 `app/__init__.py` 元数据一致
- **测试素材**：`backend/tests/fixtures/` 新增两份 docx 简历（Java 后端 3 年高匹配 / 前端转后端低匹配）+ 一份共用 JD 文本，已通过 `parse_resume_file` 冒烟，用于 A/B 对照诊断与消融复跑

**遇到的问题与解决**
| 问题 | 解决 |
| --- | --- |
| 编辑器 `taskId` 此前为必选路由参数，存档键直接拼 taskId，空值会把 key 变成 `resume_edit_undefined` | `taskId = route.params.taskId || ''`，键名统一 `_${taskId || 'blank'}`；`loadData()` 在空白模式跳过 sessionStorage/后端三层回退 |
| 编辑器模板「添加」按钮依赖区块 v-for，教育/经历初始空数组时无入口 | 已确认模板自带「+ 添加教育经历 / + 添加工作经历 / + 添加项目」与空态提示，空白起步可完整填写 |

**验证**：`npm run build` 过；docx 解析冒烟过（819/597 字）；`/editor` 页面待下次打开应用时人工确认。

## M14 导出体验升级（2026-09-21）

**修改内容**
- 桌面端 Word 导出改为**原生「另存为」对话框**选保存路径（`desktop.py` 新增 `DesktopApi` js_api 桥），服务端直写所选路径，保存位置明确可见；网页形态保持浏览器下载
- 新增**导出历史**：`export_history` 表 + `GET/DELETE /resumes/export-history` 接口；编辑器顶栏「导出历史」弹层可查看最近 30 条（时间/文件名/保存路径），桌面态可一键「打开位置」（资源管理器选中文件），网页态标注「浏览器下载」
- **PDF 导出修复**：打印从 ResumePreview HTML 模板改为**直印 docx 预览 DOM**——打印输出、屏幕预览、Word 导出三者版式完全一致（此前打印用的是另一套 HTML 模板，与 Word 排版存在偏差）

**遇到的问题与解决**
| 问题 | 解决 |
| --- | --- |
| 桌面 webview 里 blob 下载落进系统下载目录，用户不知道文件在哪 | pywebview `create_file_dialog(SAVE_DIALOG)` 选路径 → `export-docx` 带 `save_path` 服务端直写；后端校验仅桌面形态可用（网页形态禁写用户任意路径）、绝对路径、.docx 后缀、父目录存在 |
| pywebview `create_file_dialog` 返回值版本差异（str / list） | 兼容处理：list/tuple 取首个，空返回 None 视为用户取消 |
| 打印内容与 Word 导出版式不一致（旧问题 I-01 的打印残余） | `downloadPdf()` 把 docx-preview 渲染的 DOM 快照注入打印区 `v-html`，打印后清理；CSS 增加 `.docx-wrapper` 去灰底/去阴影适配；预览未就绪时回落 ResumePreview |

**验证**：pytest 22 过；`npm run build` 过；桌面态待重新打包后实测对话框与「打开位置」。

## M12 检索质量 + 防幻觉加固（2026-09-21）

**修改内容**：evidence.py 检索打分升级 BM25-lite（IDF 加权 × √查询覆盖度 ÷ √块长度）；gap/rewriter prompt 增加空证据池防幻觉指令。

**遇到的问题与解决**
| 问题 | 解决 |
| --- | --- |
| 「负责/项目」等高频通用词与 Kubernetes 等区分词同权，检索排序不准 | BM25-lite 打分：IDF=`log(1+N/df)`，DF 表缓存在索引上每任务复用 |
| 消融实验发现空池下模型仍幻觉出恰好合法的证据 id（如 R1） | prompt 明令空池留空 + `filter_valid_ids` 校验双保险；消融 B 变体需「检索+校验双禁」才构成有效消融 |

**验证**：pytest 22 过；真实 LLM E2E 引用率 5/6 → 6/6；消融结论跨运行可复现（RAG +8 分）。

## M11 RAG 证据接地 + 动态多轮追问（2026-09-21）

**修改内容**：新增 `core/evidence.py`（分块/索引/检索/校验四步流水线，embedding 不可用自动降级 IDF 关键词检索）；scorer/gap/rewriter 三节点证据接地；LangGraph `clarify_plan/clarify_wait` 双节点 + `interrupt()` 人在回路动态追问（0-3 问）；`POST /live/clarify` 暂停恢复链路；前端追问卡片 + 差距条目 `[R*]` 证据引用展示；`scripts/evaluate.py` 稳定性+消融评估。

**遇到的问题与解决**
| 问题 | 解决 |
| --- | --- |
| Python 3.10 下 async 图 `interrupt()` 失效（contextvars 行为 3.11+ 才正确） | 官方兼容解：交互图同步节点包装 + worker 线程驱动同步 stream；离线图保持 async |
| clarify_plan 恢复时重复 LLM 调用 | 节点**先提交 state 再 interrupt**，恢复时跳过规划直接读 state |
| 空池下 LLM 编造证据 id | 防幻觉四层体系（见技术说明 6.8.3） |
| 评估脚本首次运行 ImportError | 修复模块导入路径后重跑 |

**验证**：22 项 pytest（含暂停/恢复集成测试）；真实 LLM E2E（glm-4-flash）追问→回答→续跑全链路通过；消融：RAG 贡献 +8 分、引用率 100% vs 0%。
