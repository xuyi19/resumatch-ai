## 优化⑬ 设置页分组导航：四组分区 + sticky 锚点 + 指引折叠（2026-10-10）

> 用户反馈「常有的位置有点难受」：7 张卡平铺一长条，「获取 Key 三步指引」教学大卡常驻中部（已配置用户全是噪音），危险操作（清空数据）夹在中间，无分组无导航

- **危险操作置底**：「清空我的全部数据」随数据与隐私卡移到整页最末
- 页头副标题从「配置大模型 API…」改为覆盖全页的「管理模型服务、招聘数据源与本地数据；Key 与数据仅保存在本机」

- **新增 `utils/pdf_generator.py`**：`generate_resume_pdf(data, template, photo_path)`——入参数据模型与 docx 生成器完全一致（编辑器 buildWordData 产物双轨同源）；配色复用 `docx_generator.TEMPLATES` 模板色板（同一模板参数下 Word/PDF 观感一致）；A4 版式（姓名页眉 + 求职意向/联系方式 + 区块标题细线 + bullet 正文 + 技能「 · 」连接 + 证书），ASCII 词不折断的贪婪换行、内容超页自动分页；证件照右上角一寸照嵌入（照片读取失败回退纯文字页眉）

- **端点 `POST /resumes/export-pdf`**（与 export-docx 同构）：抽公共 `_resolve_photo`（照片校验）与 `_deliver_export`（双形态投递：桌面态 M71 统一落盘「简历」子目录 + 导出历史；网页态 blob 下载），export-docx 一并复用去重

- **测试**：新增 `test_pdf_export.py` 8 例（生成器渲染 / 空数据与未知模板回落 / 分页不丢内容 / 照片嵌入 / 端点 blob+历史 / 照片 404 / 桌面态落盘「简历」子目录 / web 403）

## 优化⑩ 面试对话流式 SSE：面试官回应 token 级渐进渲染（2026-10-09）

> 模拟面试此前 POST /interview/chat 整段等 3~8s 才出回应；本轮对齐打字机体验，首字延迟降至首 token

- **后端新增 `POST /interview/chat-stream/{task_id}`**（SSE）：langchain `astream` token 流式调用，事件序列 start → delta（发言增量）→ stage（summarizing 总评中）→ final（与 /chat 回包结构完全一致）；异常走 `event: fatal`
- **增量解码**：`_JsonFieldStream` 字符状态机从模型 JSON 输出 `{"reply": ...}` 中边收边解码 reply 字符串值（支持转义/`\uXXXX`），流结束后仍按完整文本严格解析 advance
- **三级降级**：模型输出 JSON 不合法但已流出发言 → 保留文本、advance 安全置 false；astream 中途抛错 → 非流式 call_llm_for_json 重试一次并补发未流出部分；会话校验失败 → 开流前正常 HTTP 4xx
- **落库零改动**：_prepare_chat / _apply_turn / _gen_summary 与非流式端点共用，chat_log / answers / 收尾总评逻辑不变；commit 先于 final 事件保证前端拿到 final 时状态已持久
- **前端**：api/index.js 新增 fetch + ReadableStream 版 interviewChatStream（axios 浏览器端不支持流式）；InterviewPanel 发送后首个 delta 挂面试官气泡渐进填充，自动滚动跟随；流式失败自动降级非流式端点重试，双重失败才回滚提示
- **总评等待可视化**：末题收尾时后端发 stage 事件，界面显示「面试结束，正在生成总评…」
- 旧 /chat 端点保留作为降级兜底；验证：pytest **187 passed**（182+5，含流式全流程/强制收尾+总评/JSON 中断降级/流错误降级/开流前校验）+ vitest 11 + build 全绿

## 优化⑥ Arco UI 按需引入（2026-10-09）

> 最大剩余肥肉：arco chunk 1156 kB（gzip 285 kB），全量引入却只用到 1 个模板组件 + 2 个函数式 API

**改造**（[main.js](frontend/src/main.js)）：
- 去掉 `import ArcoVue from '@arco-design/web-vue'` + `app.use(ArcoVue)` — 组件不再全量注册
- 去掉 `import '@arco-design/web-vue/dist/arco.css'` — CSS 不再全量引入
- 保留 ArcoVueIcon（图标全量，按需成本高，留待后续）
- 手动注册 `<a-modal>`：`app.component('a-modal', Modal)`（唯一模板组件）
- 手动引入两个函数式 API 的 CSS（级联自动拉基础样式 + Modal 内部依赖的 Button）：
  - `@arco-design/web-vue/es/modal/style/css.js`
  - `@arco-design/web-vue/es/message/style/css.js`
- 各视图已局部 import `Message`/`Modal`，函数式 API 不依赖 `app.use(ArcoVue)` 即可用

**体积对比**：
| 指标 | 前 | 后 | 缩减 |
|------|----|----|------|
| arco.js | 1156 kB | 509 kB | **-647 kB / -56%** |
| arco.js gzip | 285 kB | 88 kB | **-197 kB** |
| arco.css | ~150 kB | 51 kB | **-99 kB / -66%** |
| JS 总量 | 2.23 MB | 1.59 MB | **-640 kB / -29%** |

**踩坑**：`css.js` 会自动级联依赖（modal → 基础样式 + Button；message → 基础样式），不需要手动一层层引；函数式 API（Message/Modal）与组件注册（`app.use`）是两条独立路径，import 即可用；图标全量 ArcoVueIcon 占了 509 kB 里的大部分，按需引图标可再缩 ~200 kB（成本高，留待后续）。

## M17 Web 形态压力摸底（2026-09-22）

**修改内容**
- 新增 `backend/scripts/stress_web.py` 压测脚本：进程内 uvicorn（port=0 随机端口）+ mock LLM 每节点延时 8s 拉长任务窗口；① 单诊断任务上阶梯开 25/50/100/150 条 SSE 连接（每波保持 7s），测首包延迟与进程内存 ② 20/60/120 工作循环并发插入 diagnosis_records（模拟进度节流写的极端化），测吞吐与锁错误；数据全部落 `tests/.tmp/stress/`

| 问题 | 解决 |
| --- | --- |
| `logging.getLogger("sqlalchemy.engine").setLevel(WARNING)` 放在 app 导入前不生效 | engine `echo=True` 在创建时强制重设 INFO——日志抑制必须放在 `app.core.db` 导入**之后** |
