# 产品化完善计划（从「功能完整」到「实打实满足用户」）

> 定位：M1-M17 完成的是「功能可用」；本计划回答一个问题——**一个真实求职者拿它找工作，顺不顺？**
> 以用户旅程为主线找断点，按「核心闭环 > 上手门槛 > 容错信任 > 收尾」排优先级。
> 配套文档：[`改造计划.md`](改造计划.md)（M1-M17 迭代史）、[`ResuMatch-AI-技术说明文档.md`](ResuMatch-AI-技术说明文档.md)、[`论文准备.md`](论文准备.md)。

---

## 一、现状：用户旅程走查

当前一个求职者的完整旅程，与每个环节的状态：

| 环节 | 现状 | 断点（Gap） |
| --- | --- | --- |
| 1. 打开程序 | 首页有入口与简介 | **无示例数据**：没真实简历在手就无法体验，答辩演示也要现场凑素材 |
| 2. 输入简历 | 仅支持 PDF/docx 文件上传 | **无粘贴文本入口**：在线简历/纯文本简历用户被挡在门外；也是示例体验的前提 |
| 3. 输入 JD | 粘贴文本，≥20 字校验 | 顺畅 |
| 4. 诊断过程 | SSE 实时进度 + 动态追问 + 草稿暂存 | 顺畅 |
| 5. 看报告 | 六维评分/差距（带证据引用）/改写建议 | **报告无法导出**：想存档、发给朋友或打印都做不到，报告只活在页面里 |
| 6. 按建议改简历 | 编辑器（docx 同源预览）+ Word 导出 + 导出历史 | 顺畅 |
| 7. **验证改进效果** | — | **核心闭环缺失**：改完的简历无法「再诊断」对比 before/after，用户感知不到产品价值 |
| 8. 回看历史 | HistoryView 可回看历史报告 | **无对比视图**；无筛选/搜索，记录多了一屏拉到底；删除管理待确认补全 |
| 9. 遇到失败 | 失败态只有「返回重试」（回首页全部重来） | **部分结果被丢弃**：评分已出、改写失败时，用户时间和 API 费用白花 |
| 10. 异常输入 | 解析失败有报错 | **扫描版 PDF**（图片型）只给笼统报错，用户不知道该换文字版 |
| 11. 数据与隐私 | 数据全本机（隐私一句话） | **无清空数据入口**、无成体系的隐私说明；简历属敏感数据，影响信任 |
| 12. 版本升级 | 靠整包重发 | exe 自动更新检查（工程清单剩余项） |
| 13. 界面布局（全站走查） | 拟物风统一，但存在结构性不适 | ① **分析页 `max-w-2xl` 窄栏**：桌面宽屏两侧大片空白，表单一屏看不全（最直观的不适源）② **结果页长滚动**：无吸顶摘要条，定位信息靠滚 ③ **历史页单列卡片**：信息密度低、无筛选/搜索 ④ **对比度偏弱**：正文大量 gray-400/500 灰字 ⑤ **无设计 token**：颜色/阴影/间距任意值散落，改一处动全身 ⑥ 空态/加载态各写各的，不统一 |
| 14. 创建简历入口 | 仅首页 CTA 有「免费创建简历」 | **顶栏导航无入口**：想直接写简历的用户在任何页面都找不到（用户截图反馈）；创建→保存→诊断优化的链路未打通成主线 |
| 15. 面试功能 | 报告页有「面试准备」「模拟面试」两个 Tab | **均为「即将上线」占位**：后端 `generate_questions` 雏形已存在但未接 API；模拟面试（AI 面试官多轮对话）完全未实现——这是最令用户失望的空壳 |
| 16. 首页与功能页（用户点名） | 桌面端启动落在介绍首页 | **首页与功能不分离**：首页混着介绍与入口，桌面老用户每次多点一步；且用户期望功能区是**类 Codex 控制台风**（侧边栏 + 主工作区 + 终端感），与拟物风差异大 |
| 17. LLM Key 配置（用户点名） | SettingsView 可手填 api_key/base_url/model | **新用户不知道要配 Key**：首次诊断直接报错，无引导无提示；**「模型太少」体感**：后端本是 OpenAI 兼容协议（任意兼容厂商可接），但前端无厂商预设下拉，用户不知道能填 DeepSeek/Kimi/千问等的 base_url；配错时（key 无效/余额不足/模型名错）报错不明确，也无连通性测试 |

**结论**：产品骨架完整，但「第 7 环节验证效果」这一核心闭环断了——用户改进简历后看不到回报；「第 13/16 环节布局与结构」要按「首页=介绍、工作台=功能」重组并整体切换控制台风格；「第 15 环节面试」是空壳占位；「第 17 环节 Key 配置」是新用户的第一道墙——不配 Key 一切功能都不存在却无人引导；且「第 1/2 环节上手门槛」和「第 9/10 环节真实世界容错」明显粗糙。

## 二、优化项详单

### P0 —— 核心闭环（做完才算「满足用户」）

#### A1. 粘贴文本简历入口 + 示例数据一键体验
- **用户价值**：零门槛上手——没有简历文件也能 30 秒体验完整流程；答辩演示一键到位
- **方案**：
  - AnalyzeView 输入区加「上传文件 / 粘贴文本」双 Tab；粘贴文本直接走后端解析链路（resume.py 增加 text 入参分支，跳过文件解析）
  - 内置示例（直接复用 `backend/tests/fixtures/` 的高匹配简历内容 + JD 文本）：首页「▶ 30 秒看示例」按钮 → 跳分析页并自动填入示例文本
- **涉及**：AnalyzeView.vue、HomeView.vue、`api/v1/resume.py`、前端 `api.js`
- **验收**：不传任何文件，粘贴示例 → 完整跑通诊断 → 报告正常
- **规模**：S（与 D2 同页联动，一次改完 AnalyzeView，避免二次返工）

#### A2. 诊断报告导出（PDF / Word）
- **用户价值**：报告可存档、可打印、可发给学长/朋友求 second opinion
- **方案**：
  - PDF：复用 M14 打印方案（`window.print()` + 打印 CSS），新增报告专用打印样式（评分卡/差距/建议三段式）
  - Word：后端仿照 export-docx 生成报告 docx（python-docx 已在依赖内），含评分表格与建议列表；落 export_history 便于统一管理
- **涉及**：ResultView.vue、`api/v1/resume.py`（或新 report.py）、`services/export_service`（现有 Word 生成模块扩展）
- **验收**：报告页一键导出 PDF（打印预览版式整齐）与 docx（可编辑）；导出记录出现在导出历史
- **规模**：M

#### A3. 一键重新诊断 + Before/After 对比 ★最核心
- **用户价值**：补上「改简历 → 看效果」闭环，让「按建议改写」产生可感知的回报
- **方案**：
  - 编辑器/报告页提供「用当前简历重新诊断」：沿用同一 JD 上下文发起新任务（记录来源 parent_task_id，便于溯源）
  - HistoryView 增加对比视图：勾选两条记录 → 雷达图叠加对比（六维分）、综合分变化、差距条数变化、新旧建议对照
  - 报告页顶部显示「较上一次诊断 +5 分」式的增量提示（同 parent 链自动对比）
  - DB：diagnosis_records 加 `parent_task_id` 列（走 `_SCHEMA_NEW_COLUMNS` 登记惯例）
- **涉及**：EditorView.vue、ResultView.vue、HistoryView.vue、`live.py`、`entities.py` + `db.py`
- **验收**：改完简历一键重诊 → 报告页直接看到分数与差距的对比；历史页任意两记录可叠加对比
- **规模**：M

#### A4. 导航「创建简历」入口 + 创建→优化链路整合（用户截图点名）
- **用户价值**：不用诊断、直接写简历成为一等公民路径——任何页面侧边栏可达；写完的简历能顺滑接入保存与诊断优化
- **方案**：
  - 工作台侧边栏导航加「创建简历」项（/app/editor），与发起诊断/历史并列（D0 壳的一部分，与首页 CTA 并存）
  - EditorView 空白创建流程完善：模板选择前置 → 编辑保存为「我的简历」（衔接 F1 简历库）→ 一键「用此简历发起诊断」（衔接 A3 重诊闭环）
- **涉及**：App.vue、EditorView.vue、router
- **验收**：任意页面侧边栏一键进入创建简历；空白创建 → 保存 → 从简历库发起诊断全链路可走
- **规模**：S（入口）+ M（链路整合，与 F1 联动实现）

#### A5. 新用户 Key 引导（用户点名，第一道墙）
- **用户价值**：没配 Key 的用户不再面对冷冰冰的报错——三步指引让 AI 功能从「不能用」变「马上能用」
- **方案**：
  - **首次运行检测**：工作台加载时查 `/api/v1/settings`，未配置 key → 弹引导层（为什么需要 / 支持哪些厂商 / 「去配置」直达设置页，可「稍后再说」但导航栏常驻小红点）
  - **拦截式提示**：分析页点「开始诊断」时未配 Key → 不发请求，弹出同款引导；失败态/空态文案附「去配置」链接
  - 设置页配 Key 区补「获取 Key 三步指引」（各厂商从官网控制台创建 API Key 的路径说明）
- **涉及**：SettingsView.vue、AnalyzeView.vue、ConsoleShell（引导层）、`api/v1/settings.py`
- **验收**：清空 Key 启动程序 → 引导层出现 → 按指引配置后诊断成功；中途配置成功后小红点消失
- **规模**：M

#### A6. 主流模型预设 + 连通性测试（用户点名「模型太少」）
- **用户价值**：选厂商 → 贴 Key → 测试通过三步接任意主流模型；不再要求用户懂 base_url 是什么
- **方案**：
  - **厂商预设下拉**：智谱 / DeepSeek / 通义千问 / Kimi(Moonshot) / 豆包(火山方舟) / OpenAI / 硅基流动 / OpenRouter / **Ollama（本地免费）**——预设自动填 base_url 与推荐 model 列表，一键应用；保留「自定义（OpenAI 兼容）」手填（后端 `ChatOpenAI + base_url` 协议已天然支持，零后端改动）
  - **连通性测试按钮**：新增 `POST /api/v1/settings/test` 发最小请求，按错误类型返回明确文案（Key 无效 / 余额不足 / 模型名不存在 / 网络不通）
  - **embedding 联动提示**：预设标注该厂商是否支持 embeddings（RAG 向量链）；不支持时提示自动回退关键词检索（降级逻辑已存在，只补提示）
- **涉及**：SettingsView.vue、`api/v1/settings.py`（test 端点）、前端厂商常量表
- **验收**：选 DeepSeek → 贴 Key → 测试通过 → 直接诊断成功；填错 Key 测试按钮给出明确原因；选 Ollama 本地模型可零成本诊断
- **规模**：M

### D. 全站风格重做（类 Codex 控制台，统一风格 + 亮/暗双主题）

> 原则：**拟物风整体替换为控制台风**——1px 细边框、小圆角、紧凑信息密度、等宽字体点缀（分数/日志/时间）、品牌紫 #6d5dfc 作 accent。**首页（介绍）与工作台（功能）必须同一套视觉语言**（同 token、同组件库、同布局骨架），只区分内容不区分风格，防割裂。**亮/暗双主题**：token 双色板，用户可手动切换，默认跟随系统。先立壳（D0）与 token（D1），再按页面动刀；布局改造与对应功能项**同页一次改完**（D2↔A1、D3↔A2/A3、D4↔A3），不返工。

#### D0. 首页/功能页分离 + 统一应用壳（用户点名，最先做）
- **问题**：首页混介绍与功能入口；桌面端启动落介绍页，老用户每次多点一步
- **方案**：
  - **路由重组**：`/` = 纯介绍页（能干什么：功能亮点卡片、诊断流程图解、面试功能预告，CTA「开始使用」进工作台）；`/app/*` = 工作台壳下的各功能页
  - **统一应用壳（防割裂关键）**：介绍页与工作台共用同一布局骨架与视觉语言——左侧固定侧边栏（Logo + 导航：介绍 / 发起诊断 / 创建简历 / 简历库 / 诊断历史 / 设置，底部主题切换 + 版本号）+ 右侧主工作区；介绍页只是主区的一篇「内容页」，不另起炉灶
  - **端差异默认路由**：桌面端（app_mode=local，经 `/api/v1/meta` 判定）启动直进 `/app`；web 端默认 `/`（新访客先看介绍）
- **涉及**：router/index.js、App.vue（重构为统一壳）、HomeView（改为介绍内容页）、新 ConsoleShell 组件
- **验收**：桌面 exe 启动直达工作台；侧边栏六入口可用；web 首页纯介绍且与工作台风格一致无割裂感
- **规模**：M

#### D1. 双主题 token 体系（全站地基，先于一切界面改造）
- **问题**：颜色/阴影/圆角任意值散落全部组件且是拟物体系（`shadow-[8px_8px_16px_#b8bcc2,...]` 遍地）；正文 gray-400/500 对比弱；无主题概念
- **方案**：
  - **语义 token**：CSS 变量 + Tailwind 映射——surface 三阶（页面底/面板底/浮层底）、border、text 三阶（主文/次文/弱化）、accent 色阶、语义色（成功/警告/危险）；组件只准用语义类，禁止裸色值
  - **亮/暗两套色板**：亮色为默认舒适主基调（用户「更舒服」诉求），暗色为终端感控制台基调；`<html data-theme="light|dark">` 切换，`prefers-color-scheme` 默认跟随系统，手动选择存 localStorage 覆盖；侧边栏底部一键切换
  - 拟物阴影类全局清除；等宽字体族（分数/日志/时间戳）进 token
- **涉及**：tailwind.config.js、全局 CSS 变量、useTheme 组合式函数、各 View/组件逐个替换
- **验收**：全站无拟物阴影/裸色值残留；亮暗两主题下正文对比均达标；切换即时生效无闪屏；`npm run build` 过 + 全页面双主题视觉走查
- **规模**：L

#### D2. 分析页重排（最直观的不适源，与 A1 联动）
- **问题**：`max-w-2xl`（672px）窄栏居中，宽屏两侧大片空白；上传+JD+选项纵向堆叠一屏看不全
- **方案**：桌面双栏 `lg:grid-cols-2`——左栏「简历」（上传/粘贴双 Tab + 我的简历快选，衔接 F1），右栏「JD 文本 + 城市选项 + 开始诊断」吸底；窄屏回落单列
- **验收**：1440px 宽屏下双栏一屏完成输入并点击开始；1280 以下不破版
- **规模**：M

#### D3. 结果页信息架构（与 A2/A3 联动）
- **问题**：报告 Tab 内评分卡/雷达/优势/差距/建议长滚动堆叠，定位靠滚；动作按钮散在页面各处
- **方案**：Tab 内容区顶部加**吸顶摘要条**（综合分 + 差距数 + 「较上次 ±N」）与页内锚点；差距条目支持按维度分组折叠；导出/重诊/编辑按钮集中右上动作区
- **验收**：任意位置一屏内可看到综合分与关键结论；点击锚点直达对应区块
- **规模**：M

#### D4. 历史页升级（与 A3 对比视图联动）
- **问题**：单列卡片堆叠、信息密度低、无筛选/搜索/批量操作
- **方案**：桌面改紧凑行列表（状态点/简历名/岗位/分数/时间一行式），加状态与时间筛选、关键词搜索、勾选两条「对比」直达 A3 视图；行内快捷操作（查看/删除）
- **验收**：20+ 条记录一屏浏览；筛选搜索可用；勾选对比可达
- **规模**：M

#### D5. 空态/加载态统一组件
- **问题**：各页空态/加载态各写各的，观感不一
- **方案**：抽 `EmptyState` / `LoadingBlock` 两个全局组件（图标+标题+副文案+行动按钮插槽），全站替换
- **验收**：所有空态/加载态走统一组件；新页面零成本复用
- **规模**：S

### P1 —— 真实世界容错（真实用户必遇）

#### B1. 失败保留部分结果 + 同任务重试
- **用户价值**：LLM 偶发失败不再「全部白跑、回首页重来」，省时间省 API 费
- **方案**：
  - `_flow` 失败时把已完成节点的部分结果（评分/差距等）随 error 一起落库（result + error 并存）
  - 新增 `POST /live/retry/{task_id}`：mock 链路同 clarify 的 Command resume 思路，从失败节点续跑（或重跑失败节点，视 LangGraph 断点能力，保底方案：携带已有部分结果整体重发但不重复收费的节点）
  - 前端失败态显示「已产出：六维评分 ✓」等 + 「重试」按钮（留在报告页，不回首页）
- **涉及**：`live_pipeline_service.py`、`live.py`、ResultView.vue
- **验收**：人为 mock 中途失败 → 页面显示部分结果 → 点重试 → 续跑成功产出完整报告
- **规模**：M

#### B2. 异常输入的明确引导
- **用户价值**：最常见挫败点（扫描版 PDF）从「莫名报错」变「一步解决」
- **方案**：解析出空文本/低文本量时返回特定错误码与文案（「检测到扫描版/图片型 PDF，无法提取文字，请换文字版或先 OCR」）；前端对症提示
- **涉及**：`services/parser`（现有解析器）、AnalyzeView.vue
- **验收**：上传一张图片型 PDF → 得到上述明确文案，而非笼统解析失败
- **规模**：S

### P2 —— 数据信任与收尾

#### C1. 隐私说明 + 清空我的数据
- **用户价值**：简历是敏感数据，「数据在哪、谁能看、怎么删干净」影响信任
- **方案**：设置页加「数据与隐私」区块：数据存储位置说明（本机 data/ 目录）+「清空全部数据」按钮（二次确认，清 DB 记录 + photos + checkpoints）；JD 仅用于本次诊断的说明文案
- **涉及**：SettingsView.vue、新接口 `DELETE /api/v1/data`（或 settings.py 扩展）
- **验收**：一键清空后：历史为空、照片目录清空、报告页无残留
- **规模**：S

#### C2. exe 自动更新检查
- **用户价值**：发出去的 exe 能提示新版本，不必挨个重发
- **方案**：启动时（桌面态）请求仓库 VERSION 文件（Gitee raw / GitHub raw 双源）对比本地版本 → 有新版则原生弹窗提示 + 打开下载页；只提示不自动下载（保持简单）
- **涉及**：`desktop.py`、仓库根 VERSION 文件（随发布更新）
- **验收**：改高 VERSION 后启动 exe 出现更新提示
- **规模**：S

#### C3. 体验细节拾遗
- 追问卡片逐条校验提示（至少答一题的具体哪题空着）
- HistoryView 记录删除/批量删除（若现状缺失）
- 窄屏（手机看 web 报告）关键页适配走查
- **规模**：S（三项合计）

### F. 功能扩展（贴合「实打实」定位的增量功能）

#### F1. 我的简历库
- **用户价值**：多份简历（不同方向投不同岗）需要统一管理，而不是每次翻文件上传
- **方案**：简历列表（缩略卡：名称/更新时间/最近诊断分）+ 重命名/删除/预览 + 「用此简历发起诊断」快捷入口；接口已具备（resume.py 上传/列表），补删除/重命名与前端管理页
- **涉及**：HomeView 或新 ResumeListView、`resume.py`
- **验收**：上传 3 份简历可管理，从列表一键对任一简历发起诊断
- **规模**：M

#### F2. JD 复用（最近使用的岗位描述）
- **用户价值**：反复投同一岗位免重贴长文本
- **方案**：保存最近 5 条 JD（标题=首行摘要 + 全文，localStorage 即可），分析页 JD 输入框下方一键选用/删除
- **涉及**：AnalyzeView.vue
- **验收**：第二次对同一 JD 发起诊断无需再粘贴
- **规模**：S

#### F3. 简历快速体检（规则版，不烧 LLM）
- **用户价值**：编辑器里秒级反馈，改一处看一处，与 2 分钟 LLM 诊断互补；也是不依赖 LLM 的工程亮点
- **方案**：纯前端规则检查清单——无量化数字（缺 %/数字）、动词弱（负责/参与）、段落过长、缺技能关键词密度、教育/经历缺失项；编辑器侧栏实时亮黄/亮红
- **涉及**：EditorView.vue + `utils/checker.js`
- **验收**：粘贴无量化示例简历 → 秒级列出对应问题项
- **规模**：M

#### F4. 差距条目标记「已解决」
- **用户价值**：改简历时逐条对照差距清单，改完打勾，形成个人任务清单
- **方案**：报告页差距条目加勾选态（存 localStorage 按任务 id），A3 重诊后新旧差距自动对齐展示
- **涉及**：ResultView.vue
- **验收**：标记后刷新页面状态保留；重诊对比视图中已标记项高亮
- **规模**：S

#### F5. 岗位推荐：一键获取岗位 + 按简历智能推荐（用户新增 2026-09-23）
- **用户价值**：不用自己找 JD——分析页一键拉取**真实在招岗位**，按当前简历匹配度排序推荐（附推荐理由），点选即填入 JD 直接诊断；打通「有简历 → 找岗位 → 针对性诊断」完整求职动线
- **方案**：
  - **数据源（适配器模式，只接数据 API 不爬虫）**：`services/job_market.py` 定义 `JobProvider` 协议；实现三方招聘数据 API Provider（候选：聚合数据「招聘查询」/ 天行数据 / 极速数据，按关键词+城市检索，RapidAPI JSearch 备选国际岗）+ 内置 `MockProvider`（演示/离线/未配 Key 兜底）；Provider 层做字段归一化（title/company/salary/city/jd_text/source）
  - **API**：`api/v1/jobs.py`（新）——`GET /jobs/search?keyword=&city=&page=` 拉取岗位列表；`POST /jobs/recommend`（入参 resume_id）：取简历结构化摘要（技能/意向/城市）→ 关键词重合度粗筛 → LLM 精排 Top N（匹配分 + 一句话推荐理由）；LLM 复用 A6 用户配置的模型，LLM 不可用时降级纯关键词排序
  - **前端**：分析页 JD 区新增「⚡ 一键获取岗位」入口（填关键词/选城市）→ 岗位卡片列表（标题/公司/薪资/城市/匹配分/理由）→「用此岗位诊断」自动填入 jdText；推荐结果会话内缓存防重复请求
  - **配置与设置页（与 A6 模型接入完全同款体验，用户 2026-09-23 确认）**：设置页新增「招聘数据源」卡片区块，UI 复用「API 配置」的既有模式——
    - 服务商预设按钮（聚合数据 / 天行数据 / 极速数据 / 自定义），点击自动填接口地址与默认参数（实施时以各厂商接口文档为准校准字段映射）；每个预设带「前往控制台获取 Key ↗」直达外链（与 A6 模型预设同款）
    - API Key 输入 + 「测试连接」按钮：新增 `POST /api/v1/settings/test-job`，发一个最小检索请求验证，错误按类型归因（Key 无效 / 免费配额用尽 / 网络不通），与 `test-llm` 同款文案风格
    - 「保存配置」生效；Key 仅存本机 localStorage（`job_source_config`），与模型 Key 同等隐私待遇；未配置时分析页隐藏「一键获取岗位」入口并提示可手动粘贴
- **风险与兜底**：三方 API 配额/失效 → Provider 健康检查 + 明确报错 + 回退手动粘贴；JD 进入诊断链路仍以「填入输入框的文本」为准，**不改诊断链路输入方式**（与 M18 F2 JD 复用栈共存）
- **涉及**：`api/v1/jobs.py`（新）、`services/job_market.py`（新）、`api/v1/settings.py`（test-job 端点）、AnalyzeView.vue、SettingsView.vue（招聘数据源区块）、`api/index.js`
- **验收**：设置页选「聚合数据」预设 → 贴 Key → 测试通过 → 保存（与模型接入同款三步）；分析页「一键获取岗位」→ 出现真实岗位并按当前简历给出匹配分与理由 → 点选岗位自动填入 JD → 直接发起诊断成功；未配数据源时入口隐藏、手动粘贴不受影响
- **规模**：M

### G. 模拟面试落地（占位 Tab 变实装，用户点名）

> 定位：LangGraph 人在回路多轮 Agent 的**第二个应用点**——与诊断链共用 checkpointer/SSE/证据池基建，把报告页两个「即将上线」空壳变成完整功能，论文的 Agent 叙事更完整。

#### G1. 面试准备题单（先落地，成本最低）
- **用户价值**：知道自己会被问什么、考察点是什么、怎么准备
- **方案**：后端 `interactive_opt_agent.generate_questions` 雏形已存在——补 API 端点（`POST /interview/questions`），按三类生成 8-12 题：技术考察点 / 项目深挖（基于简历项目 + 证据池，天然衔接 RAG 引用）/ 行为面；前端报告页「面试准备」Tab 实装：分类分组、每题含考察点与回答提示、可复制
- **涉及**：`api/v1/interview.py`（新）、interactive_opt_agent、ResultView 面试准备 Tab
- **验收**：报告页一键生成题单，内容引用简历真实项目而非泛泛八股
- **规模**：M

#### G2. AI 面试官多轮对话（核心）
- **用户价值**：报告页「模拟面试」空壳变实装——像真实面试一样被追问，练表达
- **方案**：LangGraph 会话图（与诊断图解耦，复用 SqliteSaver checkpointer）：开场白 → 逐题提问 → 用户作答 → 即时点评 + 决定追问或下一题（答得好深挖、答不上给提示）→ 可「结束面试」随时退出；追问深度设上限防跑飞；对话 SSE 流式输出复用 live 基建；会话跨重启可恢复（M16 基建白拿）
- **涉及**：`agents/interview_graph.py`（新）、`api/v1/interview.py`、新 MockInterviewView（或报告页 Tab 内嵌）
- **验收**：完整 5 题对话往返；点评切题且引用简历内容；中途刷新页面会话可恢复
- **规模**：L

#### G3. 面试评价报告
- **用户价值**：练完有复盘——每题表现与整体建议
- **方案**：对话结束后节点汇总：每题表现（亮点/不足/参考答案要点）+ 整体评分与改进建议；落库关联诊断记录，历史可回看，支持导出（复用 A2 报告导出通道）
- **涉及**：interview_graph 收尾节点、entities（会话记录表或复用 diagnosis_records 加 kind 字段）
- **验收**：结束面试出报告，历史页可回看，可导出
- **规模**：M

## 三、里程碑与顺序

> 布局改造与功能改造**按页面合并**推进（同一页面只动一次刀）；用户点名的「创建简历入口」「模拟面试」优先排入。顺序：地基 token → 上手与入口 → 核心闭环 → 模拟面试 → 扩展功能 → 容错 → 收尾。

| 里程碑 | 内容 | 说明 |
| --- | --- | --- |
| **M18 风格重做 + 上手 + 入口** ✅ 已完成（见《改造计划》） | D0 统一壳与页面分离 → D1 双主题 token（亮/暗）→ D5 统一空态 → A4 侧边栏「创建简历」入口 → A1+D2 分析页（粘贴/示例 + 双栏重排）+ F2 JD 复用 → A5 Key 引导 + A6 模型预设/连通性测试 | 壳与 token 是后续界面项的地基；介绍页与工作台同风格防割裂；新用户「配 Key」这道墙已在 M18 打掉 |
| **M19 岗位推荐**（用户新增，下一站） | F5 一键获取岗位（三方招聘数据 API）→ 按简历 LLM 精排推荐 → 点选填入 JD 直接诊断 → 设置页「招聘数据源」配置 | 用户点名优先排入；只接数据 API 不爬虫；MockProvider 兜底保证演示永不落空 |
| **M20 闭环 + 报告** | A2+D3 报告导出 + 结果页信息架构 → A3+D4 重诊对比 + 历史页升级 | 补上「改简历 → 看效果」核心闭环 |
| **M21 模拟面试** | G1 面试准备题单 → G2 AI 面试官多轮对话 → G3 评价报告 | 用户点名；LangGraph 第二应用点，工作量大单独成里程碑 |
| **M22 功能扩展** | F1 简历库（含 A4 创建链路整合：保存进简历库）→ F3 快速体检 → F4 差距标记 | 围绕「多简历、多岗位、逐条改进」的使用方式；F1 落地后与 F5 推荐天然联动（多份简历分别推荐） |
| **M23 真实容错** | B1 部分结果+重试 → B2 扫描 PDF 提示 | 依赖 M16 快照/恢复基建 |
| **M24 信任收尾** | C1 隐私与清空 → C2 exe 更新检查 → C3 细节拾遗 | 发布前收口 |

每个里程碑照旧走「实现 → pytest/npm build 全过 → 更新三件套文档 → 用户确认 → 提交推送 → 需要时重打包」的既定流程。
