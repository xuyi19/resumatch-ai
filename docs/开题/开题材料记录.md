## 三、开题报告全文（可直接复制修改）

### 一、本课题的研究背景及意义

随着高等教育规模的持续扩大，高校毕业生就业竞争日趋激烈。据教育部统计，2025 届全国普通高校毕业生规模预计达 1222 万人，再创历史新高（教育部，2024）。在校招场景中，求职者普遍面临两个突出痛点：其一，人岗信息不对称，求职者难以判断自身条件与目标岗位的匹配程度，只能凭感觉大量海投简历，导致投递反馈率低、求职周期拉长；其二，简历优化缺乏针对性，市面上的简历工具大多停留在格式美化与通用性打分层面，无法结合具体目标岗位的任职要求给出差异化改进方向，更难以直接给出可用的改写结果。

与此同时，以 GPT 系列为代表的大语言模型（Large Language Model, LLM）在文本理解、信息抽取与内容生成方面已具备接近实用的能力（车万翔等，2023），为解决上述痛点提供了新的技术可能。然而，若仅以单一提示词「一问一答」的方式让通用大模型点评简历，其输出往往存在三大缺陷：结论发散不稳定、缺少中间推理过程、评价观点无法回溯到简历原文，甚至存在编造「幻觉」风险，难以满足求职场景对可信度的要求。

本课题面向上述现实需求，设计并实现一套基于大模型的智能简历诊断与岗位匹配推荐系统。其实践意义在于：将通用的模型能力转化为面向求职场景的结构化、可解释、可交付的完整服务，一方面针对目标岗位对简历进行智能诊断并给出可用改写结果，另一方面基于简历与岗位的语义匹配实现个性化岗位推荐，帮助求职者明确「我适合什么岗位、简历差在哪、如何改」，从而提升求职效率与人岗匹配质量。其技术意义在于：探索多智能体工作流编排与检索增强生成（RAG）证据接地技术在垂直领域的工程化落地方案，为构建可信、可解释的大模型应用提供一种可参考的系统范式。

### 二、国内外研究现状

**（一）国外研究现状**

在基础模型层面，Transformer 架构的提出奠定了预训练语言模型的技术基础，GPT-3 证明了大规模语言模型的少样本学习能力，GPT-4 进一步将多轮对话、指令遵循与结构化输出能力推向实用水平（车万翔等，2023）。在知识增强方面，检索增强生成（RAG）范式通过先检索后生成的方式显著提升了模型输出的事实性与可溯源性，目前已成为大模型落地应用的主流技术路线之一。在应用编排方面，以 LangChain、LangGraph 为代表的开源框架将有状态工作流图、检查点与中断恢复等原语引入大模型应用开发（中国信息通信研究院，2024），推动了多智能体协作系统的快速发展。在求职辅助产品方面，国外已有 Simplify Copilot 等半自动投递工具，通过统一档案与表单预填辅助用户批量申请职位，但其自动化集中在「投递」环节，并不解决简历与岗位的匹配诊断问题；而以 AIHawk 为代表的全自动投递项目则因招聘平台的反自动化风控而屡受限制。

**（二）国内研究现状**

国内方面，各大招聘平台陆续内建了 AI 简历优化、智能点评等辅助功能，但多为平台生态内的点状工具，覆盖场景有限。通用大模型（如文心一言、通义千问、ChatGPT 等）的普及使得「让 AI 帮我看简历」成为常见用法，但直接问答式点评存在前述输出发散、无证据支撑等问题，难以直接产出可用的改写结果。传统简历工具（各类模板站与评分工具）则以格式检查与通用建议为主，缺乏对具体岗位任职要求的针对性分析。在学术与开源社区，基于大模型的多智能体协作框架（如 AutoGen、MetaGPT 等）近年受到广泛关注，为复杂任务的分角色编排提供了新的技术路径，但将其系统性地应用于「简历—岗位」匹配诊断并保证结论证据可溯的公开研究与实践仍较少。

**（三）简要评述**

综上所述，现有工作或集中于投递环节的流程自动化而面临风控与合规风险，或停留在通用化的简历打分与建议层面而缺乏岗位针对性，亦缺少面向个人简历的个性化岗位推荐；大模型直接问答虽具潜力，但结论发散、证据不可溯的问题尚未在求职场景中得到系统性解决。如何将多智能体工作流编排与证据接地技术相结合，构建「结论可解释、证据可回溯、结果可交付」的智能简历诊断与岗位匹配推荐系统，是本课题拟探索的方向。

### 三、本课题的研究（设计）的主要内容、方法或技术路线

**（一）主要研究内容**

本课题设计并实现一套基于大模型的智能简历诊断与岗位匹配推荐系统，主要研究内容包括五个方面：

1. 基于状态图的智能简历诊断工作流。将简历诊断任务拆解为简历解析、岗位分析、多维评分、差距分析、简历改写等职责单一的智能体，以 LangGraph 有向状态图进行编排；解析阶段并行化处理以缩短耗时，追问阶段利用中断（interrupt）原语实现「人在回路」的动态暂停与恢复，由模型根据信息缺口自行判定追问数量，并支持断点续跑。
2. 任务内证据接地方法。区别于外挂知识库式 RAG，将当前简历与岗位描述切块建立临时检索索引，使每条评分、差距结论与改写建议均可回链简历原文证据；设计「证据注入、引用约束、输出校验、推断标注」四层防幻觉机制，保障诊断结论可信、可解释。
3. 岗位匹配推荐方法。聚合多来源在招岗位构建岗位库，采用「关键词重合度粗筛 + 大模型语义精排」的两阶段匹配策略：先以词汇重合度等可计算特征快速过滤候选集，再由大模型结合简历内容对候选岗位逐一评分排序并给出推荐理由，在控制调用成本的同时保证推荐的语义相关性；针对岗位描述与简历的匹配结果输出匹配分与差距说明，与诊断结论互相印证。
4. 流式交互与结构化输出工程。基于服务器推送事件（SSE）实现诊断进度与对话内容的实时推送；针对异构大模型结构化输出不稳定的问题，设计「模式注入、括号平衡提取、纠错重试」三层容错方案，兼容不同厂商模型的即插即用。
5. 系统实现与评估。采用前后端分离架构（FastAPI + Vue3），完成简历诊断、岗位匹配推荐、简历优化导出等功能模块的开发，并以桌面免安装与网站双形态交付；构建稳定性、消融与压力测试相结合的评估体系，验证系统的有效性与可用性。

**（二）研究方法**

本课题采用文献研究法梳理大模型应用与求职辅助工具的研究现状，提炼现有工作的不足；采用原型系统法，以迭代方式完成系统设计、开发与功能验证；采用实验验证法，通过消融实验对比证据接地模块启用前后的诊断质量差异，通过重复实验与压力测试评估系统的稳定性与并发性能，并采用对比分析法评估岗位匹配推荐结果的相关性与可用性。

**（三）技术路线**

系统整体采用分层架构：交互层基于 Vue3 实现网页界面并打包桌面客户端；服务层基于 FastAPI 提供接口与 SSE 推送；编排层以 LangGraph 组织多智能体诊断链，实现并行解析、条件分支与动态追问；能力层通过统一封装调用 OpenAI 协议兼容的大模型服务，结合任务内 RAG 证据库与四层校验机制保证诊断输出质量，并提供「粗筛 + 精排」两阶段岗位匹配推荐能力；数据层采用 SQLite 存储简历、岗位库、诊断记录与会话数据。开发过程遵循「需求分析、总体设计、模块实现、集成测试、部署交付」的软件工程路线。
